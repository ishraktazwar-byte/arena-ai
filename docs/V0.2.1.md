# V0.2.1 — persistent structured memory

## Scope
One coherent increment: durable, bounded local event memory feeding strategy.
No new combat, provider, building or civilization behavior is claimed.

### Records
Schema-v1 records contain an ID, timestamp, world ID, dimension, position, kind,
provenance and strictly validated data. Supported kinds:
- spawn / death / observation: local health and food evidence;
- goal_result: known tool name and completed/blocked/cancelled/failed outcome.

Raw chat, model reasons, environment objects, credentials, arbitrary code and
unrecognized result fields are not persisted. Inventory/resource discovery and
social/relationship memory are not implemented by this version.

### Storage and recovery
Per-agent files under ignored runtime/agents/<agent>/:
- memory.json: current validated snapshot;
- memory.backup.json: previous validated snapshot;
- memory.lock/: exclusive writer lock and temporary replacement file.

Writes are serialized, flushed to a temporary file and renamed into place.
The prior in-memory snapshot is backed up before each primary replacement.
Invalid primary snapshots can recover from a validated backup and repair the
primary. If both copies are invalid, startup fails; future schema versions do
not silently downgrade. A crash lock fails closed and requires checking that
all processes for the agent have stopped before manual removal.

Retention is the last 500 records total per agent, across worlds. Old important
records can eventually be evicted: this is bounded history, not lifelong memory.
At most eight records from the current world AND dimension enter a plan. Ranking
uses recency, proximity and event importance; death is evidence of an event,
not proof that a location is always hazardous. Unknown dimensions yield no recall.

MC_WORLD_ID is an explicit stable world label. Keep it across address changes;
change it on world reset. The host:port fallback cannot automatically recognize
that Aternos changed ports or that a server regenerated its world.

### Runtime integration
Memory ownership is acquired before Minecraft login. Spawn/death writes are
queued without awaiting disk in the reflex path. Strategic observations are
stored before planning, and validated history is supplied as untrusted context.
Interrupted actions are remembered as outcomes, never resumed automatically.
A lifecycle change during slow storage prevents a stale provider request.
Shutdown/disconnect drains pending strategic recording before closing memory.

## Validation
81 automated tests pass locally on Node 22.22.3 and Node 24.21.0. Syntax checks
and git diff whitespace checks pass. V0.2.1 GitHub CI is tracked separately on
Windows/Ubuntu with Node 22/24; results must be checked, not inferred.
New coverage includes restart persistence, world/dimension boundaries, duplicate
writers, ordering, drained shutdown, corruption recovery, unsupported schemas,
oversized files, field filtering, retention, orphaned locks, failed-write retry,
restart-aware planning, interrupted-goal recording and slow-storage invalidation.

## Limitations and honest guarantees
- No live Minecraft/cloud validation; tests use simulated bodies/provider output.
- Backup recovery may lose the most recent transaction. This is not a database
  journal or a promise against every power-loss/filesystem failure.
- File contents are fsynced, but cross-platform directory-metadata durability is
  not guaranteed. Memory is not encrypted; gameplay coordinates are private data.
- Strategy can continue safe fallback after a runtime write failure and emits a
  sanitized error; failed writes do not silently become successful memory records.
- New schemas need explicit future migrations. No embeddings, knowledge graphs,
  social learning, automatic hazard-map avoidance or unfinished-plan resumption.
