# V0.2.12 — mature-crop discovery and harvesting

## A food-production skill, not a scripted farm routine

Adds scan_crops and harvest_crop. The planner may independently choose which
observed mature crop to harvest, or ignore it. No prescribed farm-building story,
walking routine, replanting loop or approval prompt is introduced.

Autonomous-world mode enables harvesting alongside the existing skills. Restricted
mode uses separate MC_FARMING_ENABLED, DIMENSION and AREA settings, parsed through
the existing trusted deployment policy. World mode ignores those restricted-mode
fields and reports that fact in its startup policy diagnostic. A shared-server
crop is not assumed unowned merely because it is ripe; ownership is not detected.

## Discovery and maturity

A fixed 9×5×9 local search returns up to 16 visible plants, using the existing
four-block sampled line-of-sight check. Supported crops are wheat, carrots and
potatoes at age 7, and beetroots at age 3. Immature plants remain observable but
ineligible. Missing, invalid or unsupported age metadata is not guessed.

The pinned Prismarine Minecraft 1.21.1 block API returns these integer properties
as strings. Dependency inspection caught that detail during implementation; the
reader now accepts exact single-digit strings or integer values within each crop's
range. Contract tests exercise both mature and immature real block state IDs.
Arbitrary text, NBT and names outside the four crop types are not exposed.

## Guarded harvest

- One currently mature, visible crop at the body's floor level or one block above,
  over known farmland, outside the body's column, and within farming permission.
- Minecraft Java 1.21.1, grounded on known safe solid support, NORMAL risk, known
  vitals, health at least 8, and no open container, cursor item or crafting-grid
  content. Hunger alone does not forbid this motionless food-gathering action.
  Other tools, including collection, keep their existing preconditions.
- Use an already empty hand or synchronously select an empty hotbar slot. Do not
  equip/unequip, transfer inventory stacks or toss an item. A full hotbar with a
  held item is refused. Failure may leave the selected hotbar slot changed; no
  equipment rollback is attempted after a new controller takes ownership.
- Guard the original body/dimension, aim, crop name/state/maturity, exact farmland
  state and empty hand before digging. Reach/visibility and body/site checks run
  again during the operation. Unknown terrain, changed soil, danger or changed
  equipment stops the attempt. Moisture-state changes can conservatively refuse
  a harvest even if the support is still farmland.
- Dig with the pinned helper's ignore-look mode after guarded aim, avoiding a late
  unguarded internal aim. Dig duration must be at most two seconds. Aim is bounded
  to 1.5 seconds; completion/confirmation to predicted dig time plus 1.5 seconds;
  the registry's overall action timeout is six seconds. Active checks run every
  50 ms. There are no movement, jumping, sprinting or replant commands.
- Require the dig operation to finish without rejection AND an inbound block_change
  report of air at the target. Optimistic cache air, unrelated packets and entity
  animations are not sufficient. Listeners/monitors are removed on all exits and
  synchronously through the arbiter's cancellation cleanup.

FARMING-RESULT reports server-observed removal, not exclusive causality, expected
yield or collected food. A different actor could remove the same plant. Results
explicitly report dropsCollected=not_verified and replanted=false. Farmland is not
dug, but the tool does not claim a server-confirmed guarantee that the soil was
unchanged by other actors. Cancellation cannot undo already-issued actions.

## Integration and persistence

Crop observations enter runtime planning context. The tool catalog carries the
same copied deployment scope used at execution. scan_crops remains read-only and
is excluded from failed-action cooldowns; harvesting uses the existing cooldown
and short-plan interruption rules. Plans cannot bypass maturity checks or request
arbitrary block types, bulk harvest counts or a hidden replant operation.

Memory writer schema 9 reads schemas 1–8 and records scan/harvest outcomes as
history. The supply-objective vocabulary additionally includes wheat, potato,
beetroot and their supported seed items. An objective does not claim food is
edible or a planting/cooking skill exists. Crop maturity is current observation,
not persisted as an eternally ripe resource landmark.

## Verification and limitations

Tests cover strict goals, world/restricted policy, bounded discovery, immature and
malformed ages, actual pinned block metadata, empty-hand selection, full hotbars,
hunger versus unknown vitals, danger, footing, inventory state, soil/crop changes,
world/body invalidation, cancellation during aim/dig, cleanup, missing/wrong
acknowledgements, dig rejection, stalled operations, runtime context and v8 memory
migration. Existing resource, crafting, strategy, objective and safety tests remain.

No live Minecraft/server-provider calls are claimed. Live testing remains deferred.
Replanting, growing, soil preparation, cooking and sustainable farm management are
still missing. This is harvesting capability, not a complete farming system or
proof that the full civilization platform is ready.

### Validation boundary

Maturity is the last locally observed block state. Vanilla dig packets cannot make
an atomic server-side “only if still mature” request: another actor can change or
replant the cell after the final check. Already-issued actions cannot be undone.
A later collection decision is also still subject to the existing planning interval
and item despawn; this release does not add an automatic harvest-to-pickup chain.
