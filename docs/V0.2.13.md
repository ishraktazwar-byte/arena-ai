# V0.2.13 — guarded crop planting and replanting

## Capability

Adds plant_crop for one wheat, carrot, potato or beetroot plant above an observed
empty farmland cell. The agent chooses the crop/site using its current observations
and goals. Existing short plans may combine harvest_crop and plant_crop at a known
cell, using carried reserves. No mandatory farming storyline or automatic life
progression is introduced. No new area approval is required in autonomous-world
mode; restricted mode uses the existing farming scope.

scan_crops now additionally reports up to eight nearby observed empty farmland
cells with authorized status, carried seed options and an explicit execution recheck
flag. The original bounded crop scan is reused; observation does not promise safe
reach, available hotbar staging, sufficient light or successful future growth.

## Deterministic execution and evidence

- Uses wheat_seeds, carrot, potato or beetroot_seeds according to the requested
  crop. These are finite trusted mappings, not arbitrary item/packet arguments.
- Requires the existing farming body/site checks: pinned Java 1.21.1, stable body
  and dimension, known vitals, health at least 8, NORMAL risk, grounded safe solid
  footing, clean player inventory/cursor/grid, permission and nearby visible soil.
  Like motionless harvesting, hunger alone is not prohibited.
- Requires an empty target above farmland and visible top-face interaction within
  four blocks. It never replaces an occupied plant, even one of the requested type.
  No tilling, block removal, locomotion, jumping or farmland traversal is added.
- Takes an authoritative raw inventory snapshot. Uses an already held planting
  item, an existing hotbar stack, or one guarded mode-2 main-slot-to-empty-hotbar
  swap. Main source slots are below 36 to avoid the pinned library's delayed
  post-dig hotbar-click path. No equip/unequip, cursor transfer or tossing is used.
- Main-slot staging is resynchronized and verified before hand selection. The
  selected slot must agree with authoritative seed evidence. Full hotbars without
  the needed item are refused rather than overwritten.
- After guarded aim, rechecks soil, empty cell, stable body and hand immediately
  before a narrow main-hand 1.21.1 block_place packet. It targets farmland's top
  face with cursorY=15/16; a pinned protocol serializer test covers the packet.
- Accepts only an inbound block_change for the requested crop's age-zero state at
  the target. The decoder checks the pinned registry's single age-state ordering;
  wrong crops, grown states, unrelated locations and optimistic local cache updates
  cannot establish this seedling evidence.
- Requires a final authoritative inventory snapshot showing exactly one fewer
  planting item across normal slots. Missing snapshots, no decrease, or a different
  net decrease fail confirmation. Incidental same-item pickups can conservatively
  make a real planting attempt unconfirmed.
- Checks the body/site every 50 ms and retains failures even if transient danger
  disappears before the last inventory snapshot. Cancellation removes listeners
  synchronously. A late inventory/aim result cannot send follow-on commands after
  action ownership changes.

Individual aim, inventory-sync, swap and server-response waits are bounded to
1.5 seconds. The registry caps the entire action at 12 seconds. Minecraft's internal
abandoned sync waiter may still await its eventual reply; tool guards prevent any
late follow-on action. Already-issued clicks/interactions cannot be undone. Failed
or cancelled staging may leave a different held slot/stack; no stale rollback is
attempted after a new controller takes ownership.

## What success means—and does not mean

FARMING-RESULT identifies the tool and reports a server-observed seedling plus
inventory evidence. exclusiveCausalityClaimed stays false: another actor can plant
at the same cell, and inventory can change incidentally. Vanilla packets do not
support an atomic conditional “plant only if this exact soil state remains.”
Soil changes or other actors can race the final check. Results do not promise that
the crop remains present, grows, produces yield or belongs to the agent.

The tested harvest → replant example consumes carried reserves. It does not claim
that harvested drops were automatically picked up, that seeds were replenished or
that farming is now sustainable. The default planning interval versus drop despawn
and incomplete farmland traversal still limit the broader gathering loop.

## Persistence and verification

Memory schema 10 reads schemas 1–9 and stores planting outcomes as historical goal
results, not resumable commands. There is no new world/area configuration flag and
no extra provider request per planting action. Existing request limits and local
safety priority remain intact.

Tests cover all four crop/item mappings, site discovery, shape and permission
validation, empty/full hotbars, main-slot staging and authoritative disagreements,
missing items, occupied targets, changed soil/hand/body/dimension, occlusion/reach,
preemption and cancellation during sync/swap/aim/response, wrong/missing packets,
missing consumption evidence, transient danger during final sync, synchronous
write failure, pinned state/packet contracts, v9 migration and a real guarded
harvest/replant sequence against deterministic fixtures.

No live server/provider calls are claimed. The full civilization platform is not
finished: food-loop orchestration, terrain/farm management, cooking, building,
social/economic and diplomacy systems still require substantial development.
