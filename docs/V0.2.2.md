# V0.2.2 — resource scanning and guarded mining

## Scope
A runtime registry advertises only registered, enabled tools with their trusted
schemas. The cloud strategy validates against that registry, and execution
validates again. Trusted local handlers are code; model output is only data.
Personal tool loading and arbitrary runtime plugins are not implemented.

### Resource perception
A fixed 9x7x9 loaded-block search yields at most 16 supported resource blocks
whose centers are within four blocks of the player's eye and whose sampled line
of sight is clear. Unknown/occluded resources are excluded. Observations and the
read-only scan_resources tool expose these locations. Sampling is conservative,
not a complete voxel ray tracer. Hidden neighbors may be inspected by mining
safety checks, but are not exposed as discovered resource knowledge.

### Mining
The destructive mine tool requires MC_MINING_ENABLED=true and six explicit
MC_MINING_AREA bounds plus a dimension. Defaults authorize no mining. The active
catalog includes these constraints; the execution policy is a copied snapshot
outside model control. Blocks inside an area are not automatically unowned:
operators must exclude player builds. Allowlisted blocks are logs, stone variants
and overworld/deepslate ores, not containers, machines, farmland or building tools.

One action attempts one visible block with an expected name, not an expedition.
Checks include region, dimension, stable block state, grounded/healthy/fed body,
clear sight, safe footprint, no below-foot/above-head/body-column digging, known
neighbors, no adjacent fluid/waterlogging/gravity hazards, suitable harvest tool,
remaining tool durability and bounded dig duration. There is no approach movement.

Equipment and aim are awaited separately, then revalidated before invoking
Mineflayer dig with forceLook='ignore'. This avoids its internal async-look gap
before starting the dig. Risk/geometry/equipment are monitored every 50ms.
Emergency arbitration cancels actual digging through stopDigging; stale cleanup
must not issue commands after another session owns the body. Total session is
bounded to 12s and estimated dig duration to 8s.

### Honest outcomes
Pinned Mineflayer's digging implementation optimistically calls _updateBlockState
at completion. That cache change alone is NOT confirmation. This release listens
for a matching server block_change packet with an air state. It conservatively
fails without such evidence (up to 1.5s after local dig completion). Alternative
server packet forms such as multi_block_change are not yet confirmations.
An air packet proves the server reported removal, not exclusive causal ownership
of the break when another player is nearby. Inventory gains are contemporaneous
observations, not proof that this action collected its drops.

### Compatibility
Control sessions now preserve trusted handler result data on successful actions.
The tool names scan_resources/mine can be stored as historical goal outcomes.
Memory writes schema v2, reads v1/v2, and upgrades v1 on the next write. Existing
older versions reject the new schema rather than silently downgrading history.
The resource observations are not yet persisted as a resource-map memory kind.

## Automated validation
107 tests pass locally on Node 22.22.3 and Node 24.21.0; syntax and whitespace
checks pass. Tests cover registry permission, strict schemas, bounded/occluded
scans, danger/terrain/region/equipment restrictions, asynchronous geometry
changes, cancellation during equip/aim/dig, mid-dig hazards, optimistic-cache
false positives, unrelated server packets, actual mocked confirmation, inventory
deltas, schema migration and new-tool history. Existing tests remain passing.
Windows/Ubuntu CI will be recorded after its actual run. No live server or real
cloud-provider calls are claimed by these tests.

## Remaining limitations
No guaranteed drop collection, crafting, smelting, safe long-range pathfinding,
building recognition, claims integration, tunnels, reservations or full survival.
Server physics, anti-cheat, dig-face handling, protection plugins, latency and
packet variants need live verification. Models remain optional; the no-AI fallback
still scans rather than inventing a resource-gathering plan. No dependencies added.
