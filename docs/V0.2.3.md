# V0.2.3 — guarded starter crafting

## Scope
Adds craft_options and craft to the trusted runtime registry. The planner can
request one allowlisted output item; the body chooses a supported recipe and
executes exactly one batch. Observations include bounded crafting availability.
No model-supplied recipe, click sequence, arbitrary quantity or executable code.

Outputs: eight overworld plank types, sticks, crafting tables, and wooden/stone
pickaxes, axes, shovels, swords and hoes. Inventory-grid recipes work in 2×2.
3×3 tool recipes require an already-open crafting-table window. Automatic table
placement/opening is explicitly deferred: Mineflayer's activation helper has an
internal asynchronous look before its interaction packet, requiring separate
lifecycle-safe implementation rather than a false cancellation guarantee.

## Execution safety
- Uses the pinned recipe data, checks actual output counts, supports shaped and
  simple shapeless recipes, and validates required ingredient quantities.
- Limits sources/destination to main inventory slots below 36, avoiding the
  internal hotbar-delay branch of Mineflayer clickWindow.
- Refuses occupied grids/cursors, wrong windows, unsupported recipes, missing
  ingredients, absent output space, unsafe body/footing and non-1.21.1 protocols.
- Moves one ingredient per cell with guarded individual clicks. Does not use
  Mineflayer's multi-click craft/putAway helpers or shift-click repeated crafting.
- Revalidates ownership, window and body after every await. Two-second step waits
  and a 15-second action bound prevent a stalled session from holding control.
- Session cleanup is synchronous, exactly once, before the next body owner starts.
  Requests closing only the window this action used, while alive/connected.
  A cleanup error is diagnosed without suppressing remaining registered cleanup.

## Confirmation and recovery
The pinned _syncWindow helper sends its no-op resync request before awaiting and
has no later packet writes. An incoming whole-window packet is decoded using the
1.21.1 slot format. Success requires the exact output gain and ingredient losses,
plus empty crafting slots and cursor. Optimistic local slot changes alone fail.
A concurrent server inventory change may conservatively cause verification to
fail; this is observation evidence, not proof of exclusive causal ownership.

Any interrupted/failed mutation marks crafting as needing recovery. The next
attempt must obtain a clean authoritative window snapshot first. Old await
continuations can resolve later, but ownership guards prevent subsequent clicks.
This does not undo a click already sent or promise lossless ingredient rollback.
The implementation does not explicitly toss items. Vanilla/plugin behavior for
returning/dropping cursor/grid items on close requires live testing. Mineflayer's
own wait listeners may await a later update after our bounded wait has ended;
no claim is made that its internal waits are cancellable.

## Memory compatibility
Schema v3 stores craft/craft_options goal outcomes, while reading v1/v2 snapshots
and upgrading them on the next write. Older releases reject future schemas.
Recipe plans and arbitrary model text are not persisted as resumable commands.

## Validation
130 automated tests pass locally on Node 22.22.3 and Node 24.21.0. Syntax and
whitespace checks pass. Includes real pinned 1.21.1 recipe-data contract checks
(no server connection), simulated 2×2/3×3 inventory crafting, missing ingredients,
full inventory, dirty cursor/grid, hotbar exclusion, malformed goals, unsupported
versions/windows, correct one-batch output, server evidence, bad snapshots,
interruption while clicking, changed windows, bounded hangs, recovery, cleanup
ordering, missing confirmation API, output collision and schema migration.
All earlier runtime, survival, combat, mining, memory and strategy tests pass.
Windows/Ubuntu CI results are recorded only after the release run completes.

## Still not implemented / not verified
No real Minecraft or cloud-provider validation. No automatic table opening or
placement, inventory sorting, hotbar transfers, arbitrary recipes, bulk crafting,
smelting, complete gather→craft workflow, farming, building or civilization layer.
Source review and mocks improve safety but do not replace live server testing.
No new dependencies were added.
