# V0.2.9 — autonomous-world operation

## Correcting the operating model

The target is independent agents, not bots waiting for humans to repeatedly draw
mining, collection, navigation and crafting areas. This release introduces a
single dedicated-world deployment mode while keeping restricted areas optional
for shared servers. It removes the area-configuration obstacle; it does not claim
that all strategic, production, social or civilization systems are now complete.

Set MC_OPERATING_MODE=autonomous_world and a stable MC_WORLD_ID in local .env.
There is no additional area or per-skill approval requirement. All existing gated
skills are exposed with world scope in the Overworld, Nether and End. Local tool
budgets bound each attempt, not the agent's lifetime territory. Further destinations
can be chosen on later planning cycles, without an operator extending rectangles.
No world traversal, portal construction or custom-dimension support is added.

The free-only cloud planner still requires AI_ENABLED=true and a locally configured
OpenRouter key. The existing interval and shared daily request cap remain. If AI
is off, unavailable or exhausted, observation remains the fallback—this release
does not substitute a scripted house → farm → king routine. The LLM chooses WHAT;
the deterministic body still decides HOW safely. No per-action approval interface
is introduced, and no live testing is requested or started.

## Policy precedence and migration safety

- Omitted mode defaults to restricted: upgrading an old/shared-server configuration
  must not silently authorize additional world changes.
- restricted retains independent per-tool enable, dimension and area settings.
- autonomous_world ignores ALL legacy MC_MINING/WORKSPACE/COLLECTION/NAVIGATION
  ENABLED, AREA and DIMENSION settings, even old false values. These are neither
  hidden prerequisites nor emergency kill switches in world mode. To use them,
  restart in restricted mode. Startup OPERATING-POLICY reports the selected mode,
  whether such settings were ignored and whether cloud planning is enabled.
- No implicit world identity derived from a changing server address is allowed in
  autonomous-world mode: MC_WORLD_ID must be explicit. Change it after a reset.
- Policy comes from trusted local configuration, not model arguments. Tool schemas
  still reject injected mode, area and scope fields. Catalog policies are copied;
  observations tell the planner the operating mode. Execution receives the same
  effective policy as discovery and the tool catalog.
- No key is stored in source, documentation or test fixtures. No budget or provider
  opt-in is changed by enabling world scope.

## Safety that remains

Shared permission helpers distinguish block coordinates from continuous body/drop
positions. They validate numeric bounds, supported dimensions, vanilla height and
restricted-area containment. World scope removes rectangles only—not finite-world
bounds or the existing skill checks:

- Mining remains one visible allowlisted resource block with appropriate equipment,
  safe geometry and server-confirmed removal. No claimed drop pickup.
- Collection still binds item identity and requires pickup plus inventory evidence.
- Workspace placement/use keeps guarded clicks, confirmations and late-window fencing.
- Navigation remains known-flat-terrain, six blocks per attempt, with danger checks,
  short steps, bounded time/legs and immediate cancellation ownership protection.
- Unknown terrain, stale bodies/targets, injury, danger and missing confirmation
  remain reasons to stop or refuse an action. Arrival is not server-position proof.

World mode is for a dedicated world where gathering and building are allowed. It
cannot identify another player's property, drop ownership or protected claims.
The mode is not a substitute for those future social/territorial systems. Automatic
Minecraft pickups can occur independently of tool goals. Restricted mode was and
remains tool-specific, not a universal movement fence for emergency reflexes.

## Tests and scope

New tests cover one-setting activation, migration-safe defaults, independent
restricted policies, explicit world identity, typo rejection, legacy-setting
precedence, unchanged AI budget/opt-in, dimensions/coordinate validation, copied
constraints, model non-escalation and planner selection without approvals.
Integration fixtures execute world-scoped mining, table placement, collection and
navigation; they confirm injury rejection, pickup inventory evidence and per-action
navigation bounds still apply. All existing cancellation and safety tests remain.
Memory stays schema 7: no new tool names or persisted record formats are introduced.

This release is a deployment-policy correction, not complete autonomous long-term
planning. Durable multi-step goals, richer exploration, production, the larger
population, relationships, settlement, trade and diplomacy remain unfinished.

### Review finding and fix

Expanding permission to several dimensions exposed an implicit assumption in the
older mining/workspace tools: a fixed-area dimension had served as an additional
mid-action world-change barrier. World permission must not remove that barrier.
Those actions now wrap their session guards with explicit original-body and
original-dimension checks, including after awaited aiming/equipment operations and
before subsequent writes. Navigation and collection already bind their action to
the original body/dimension. Added regressions verify no mining or block interaction
is issued after a simulated body/dimension change during aim. All prior workspace
cleanup and cancellation tests continue to pass.
